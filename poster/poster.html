01Problem

Typical library software copies the paper register: one fixed loan period for every book, a search that fails on one typo, an issue button that can lend the last copy twice, and a fines history anyone with database access can quietly edit.

02Objectives

  • OOP design: abstract Member → Student / Faculty, LoanPolicy interface, records, exceptions
  • JDBC + SQLite with one transaction per operation
  • Loans that shorten only when members are waiting
  • Race-free issue; SHA-256 hash-chained audit ledger
  • Typo-tolerant search; ISBN checksum repair
